# 吉祥物設計執行規範

版本 1.0.0 · 對象 UIUX 設計師、視覺設計師、3D 設計師與前端工程師

## 1 設計決策

角色是一位安靜、友善、帶人找到方向的陪伴者。保留珊瑚橘定位水滴、奶油色臉區與兩顆深色眼睛。以柔和的尖端收束、沒有硬邊框的臉區與克制高光，形成成熟的親和力。

固定辨識元素為完整水滴輪廓、向下收束的鈍尖端、橫向橢圓臉區、雙眼與無嘴造型。不要增加手腳、鼻子、帽子、衣物或耳朵。正式名稱由品牌團隊決定，Warm Pin 僅作檔案中的工作名稱。

本版數值是新提出的製作基準，不是從照片精密量測的數字。母版確認後，以 SVG 路徑為唯一 2D 幾何來源；不同人不要各自重新描繪。

## 2 幾何與表情

座標以 512 × 512 畫布為基準，左上角為原點。角色約寬 312、高 402 單位，置於透明畫布。保留畫布留白，避免不同表情切換時產生跳位。

| 項目     | 製作基準                                        | 驗收方式                 |
| -------- | ----------------------------------------------- | ------------------------ |
| 身體     | assets/svg/mascot-neutral-flat.svg 的 body 路徑 | 疊圖對齊，不重新自動描圖 |
| 臉區     | 中心 255,194；半徑 98,72                        | 不加黑框，不改成獨立面罩 |
| 雙眼     | 中心 217,194 與 293,194；半徑 18,25             | 基準正視，保持眼距       |
| 高光     | 每眼 1 個；半徑 5.5,4.5                         | 小尺寸版移除高光         |
| 尖端     | 底端約 257,454，平滑曲線收束                    | 不尖銳、不形成鉤狀尾巴   |
| 外部留白 | 至少角色寬度 15%，約 47 單位                    | 文字與互動元件不得侵入   |
| 伸縮     | 等比例縮放                                      | 不單獨拉寬或拉高         |

微妙的不對稱已寫入輪廓，不要每次生成隨機改變方向。SVG 的實際曲線優先於文字近似尺寸。表情只動眼睛或整體微傾，不改臉區位置與身體比例。

| 狀態    | 表現             | 適合情境           |
| ------- | ---------------- | ------------------ |
| neutral | 開眼、單一高光   | 一般引導、歡迎     |
| happy   | 向上拱的閉眼弧線 | 成功、完成         |
| curious | 雙眼輕微高低差   | 搜尋、探索         |
| rest    | 向下彎的閉眼弧線 | 暫無內容、安靜待機 |

錯誤畫面用 neutral 或 rest 搭配清楚文字。不要用責備、哭泣或誇張驚嚇表情增加壓力。成功、錯誤與載入狀態應有文字或標準 UI 圖示，角色表情不承擔唯一訊息。

## 3 色彩與材質

| Token      | sRGB    | 用途         |
| ---------- | ------- | ------------ |
| coral      | #E8836B | 身體主色     |
| apricot    | #F4B398 | 受光面       |
| terracotta | #BE5E4E | 暖色暗面     |
| cream      | #FFF1DE | 平面版臉區   |
| ink        | #352C2A | 眼睛與單色版 |
| paper      | #FBF7F2 | 暖白背景     |
| dark       | #292522 | 深色展示背景 |

上述 HEX 為 2D sRGB 顏色；3D 受燈光與色彩管理影響，請以母版視覺比對，不要求渲染中每一個像素等於主色。Soft SVG 的臉部使用 #FFF7EA 至 #F1D9C0 漸層。

3D 起始設定：非金屬、粗糙度約 0.60、金屬度 0、clearcoat 約 0.05、柔和細膩的磨砂樹脂感。這些是材質調校起點，需依渲染器修正。避免橡膠油亮感、鏡面反射、金屬、毛絨與透明玻璃。

使用正交鏡頭作正面母版。大面積主光位於左前上方約 45 度，右前側低強度補光；暖棕環境陰影，無黑色重邊。維持固定鏡頭、燈光、曝光與色彩管理，讓全套資產像同一次拍攝。臉區貼合身體，不做成厚重面罩。

## 4 尺寸與 UI 規則

| 顯示尺寸          | 建議資產               | 規則                                            |
| ----------------- | ---------------------- | ----------------------------------------------- |
| 24 至 47 CSS px   | micro SVG              | 無高光、無漸層；低於 24 px 改用產品標準定位圖示 |
| 48 至 95 CSS px   | flat SVG               | 清楚辨識優先                                    |
| 96 px 以上        | soft SVG 或正式 3D PNG | 可呈現柔和材質                                  |
| 192 至 320 CSS px | soft 或 3D hero        | 歡迎頁、空狀態，避免壓過主要 CTA                |

尺寸指包含留白的完整畫布。透明 PNG 已留邊，不要再以不同裁切方式重複輸出。深色背景使用原有彩色版並檢查輪廓；不直接把整個角色反白。mono 適用單色文件與印刷打樣，實際印刷請再做色樣。

地圖錨點為完整 SVG 畫布的 x=257/512、y=454/512。它對應尖端底部，不是畫布底部。若地圖套件只能用 bottom-center，請以外層 wrapper 修正空白偏移或另輸出經核准的地圖裁切版，並重新定義錨點。

角色可作定位輔助；所在位置、選中狀態與定位權限仍需文字及既有 UI 表達。可互動的角色應放入有明確名稱的按鈕，不直接讓裝飾圖片承擔點擊語義。建議觸控區域至少 44 × 44 CSS px。

## 5 動態規則

| 行為     | 起始參數               | 使用限制                   |
| -------- | ---------------------- | -------------------------- |
| Hover    | 240 ms，向上 2 px      | 只在可互動元件使用         |
| 成功回應 | 650 ms，小幅上移再回位 | 一次播放，不無限慶祝       |
| 待機浮動 | 3200 ms，高度約 1%     | 限展示場景；閱讀區預設靜止 |
| 轉向     | 最大正負 4 度          | 不讓定位尖端偏離錨點       |

緩動使用 cubic-bezier(.22,1,.36,1)。尊重 prefers-reduced-motion；減少動態時顯示靜態狀態。地圖上的定位角色保持固定，不使用浮動效果，避免誤導座標。動態由已確認母版衍生，不逐幀獨立生成。

## 6 生成與一致性

先確認 neutral flat SVG，接著確認正面 3D hero，再製作左右 30 度與表情。每次只改一項：視角、表情或燈光。將核准圖作為下一次編輯的參考，避免每張重新文字生成。

提示詞與 seed 不能保證角色完全一致。對正式多視角與動畫需求，優先建立同一個 3D 模型、共用材質與鏡頭。生成圖適合概念及單張視覺；要量產可控資產，必須由人員比對修正。

用正視輪廓、臉部比例與眼距判斷身份；不同視角用投影與模型一致性驗收，不拿正面比例硬套透視圖。維護 generation-log.csv，記錄工具、版本、提示詞、參考資產、日期與核准狀態。

## 7 驗收與交付

- [ ] 所有資產以同一母版衍生，文件版本與檔名版本一致。
- [ ] 24、32、48、96 px 預覽仍可辨認，眼睛未黏成一塊。
- [ ] 暖白、純白、深色與地圖背景皆檢查；透明邊緣無白邊。
- [ ] PNG 實際含 alpha 通道，沒有烘焙棋盤格；尺寸與清單一致。
- [ ] SVG 可在 Figma 和目標瀏覽器開啟；沒有外部圖片、字型或腳本依賴。
- [ ] 無嘴、無手腳、無硬黑臉框；尖端仍圓潤。
- [ ] 動態不造成版面跳動，減少動態模式為靜態。
- [ ] 地圖尖端對準指定座標，縮放或切換狀態不漂移。
- [ ] 裝飾圖使用空 alt；提供訊息的角色以清楚文字補充狀態。
- [ ] 原生 Figma、模型與動態檔交付時可編輯，並列出使用版本。

## 8 工作順序與責任

品牌／產品負責人先確認角色輪廓、名稱與應用場景。視覺設計師完成母版、表情與 3D 視覺；UIUX 設計師完成元件與真實頁面；工程師確認輸出格式、錨點與載入行為。

Gate A：母版及色彩確認。Gate B：歡迎頁、空狀態、地圖位置三個場景確認。Gate C：資產、動態、可及性與效能驗收。完成一個 gate 再擴增素材，避免整套返工。此順序為執行建議，未指定團隊工期。
