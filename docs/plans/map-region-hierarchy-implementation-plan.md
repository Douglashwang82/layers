# LocalLink 地圖分層分區 implementation plan

日期：2026-10-12。狀態：待實作。本次僅建立計畫，未修改應用程式、執行資料匯入或部署。

## 1. 目標與決策

讓使用者從「城市哪一側」逐步找到「生活圈」與「街道上的地點」：縮遠看探索大區，放大看社區，再放大看道路與店家。保留灰階低飽和底圖、滿版地圖與浮動面板，把主要色彩辨識留給 marker。

採兩個可獨立驗收的交付：先完成現有分區的縮放分層與幾何修正，再加入約 6–10 個產品探索大區。探索大區數量是設計目標，不為湊數切斷社區或補造地理資料。

本計畫延續 [分區聚焦與互動計畫](map-regions-focus-effects-plan.md) 的聚焦／篩選契約，更新其分區呈現與資料處理方向；未提及的授權、列表備援、marker 與圖層規則保持適用。配合 [極簡浮動地圖計畫](minimalist-floating-map-plan.md) 與 [地圖設計說明](../design/jade-atlas-map.md)。

## 2. 已確認的本機基準

以下為工作目錄原始碼與資產的盤點，不代表已部署或通過瀏覽器驗收。現有大量未提交變更，後續實作前必須重新確認 diff，保留其他工作的內容。

| 現況                                                            | 對本次工作的意義                                         |
| --------------------------------------------------------------- | -------------------------------------------------------- |
| registry 含 88 個 Super Neighborhoods、31 個周邊城市，共 119 區 | 社區與城市需區分視覺層級；不把 119 視為永久固定數量      |
| `map-canvas.tsx` 的兩種區域共用填色、線條與標籤規則             | 拆出按 kind、zoom 控制的呈現規則                         |
| 標籤目前在 zoom 9–13.5 顯示；區界在街道尺度仍淡淡存在           | 補完整的尺度切換及命中測試策略                           |
| 點區只聚焦；「只看此區」才更新 URL `region`                     | 維持操作語意，縮放不更改結果                             |
| `tidyCity()` 的結果直接寫入 server registry                     | 城市篩選目前也使用去碎片、填洞與強簡化後的輪廓，需先修正 |
| manifest 記錄官方社區資料涵蓋缺口與再利用條款待確認             | 不宣稱完整覆盖；發布前確認條款與署名                     |

主要檔案：

- `packages/shared/scripts/import-map-regions.ts`：匯入、城市整理、版本化輸出。
- `packages/shared/src/regions.ts`：幾何判定、bbox、遮罩與標籤位置。
- `packages/shared/src/data/map-regions/houston-super-neighborhoods.json`：server registry。
- `apps/web/src/features/map/regions.ts`、`query.ts`：區域載入、摘要、正式篩選。
- `apps/web/src/components/map/map-canvas.tsx`、`map-workspace.tsx`、`region-focus-control.tsx`：渲染與互動。

## 3. 分區資料與正確性

### 3.1 查詢幾何與顯示幾何分離

1. 保存來源完整 Polygon／MultiPolygon、洞與離散部分作為查詢幾何；不得套用 `tidyCity()` 的刪除、填洞或強簡化。
2. 保留既有 region ID，使現有 URL 持續有效。修正邊界可能改變靠近邊界項目的歸屬，需列入發布說明及回歸測試。
3. 顯示資產從同版查詢幾何產生。取消以「約二十個頂點」作為形狀目標，改用按尺度的誤差預算；共享邊界共同簡化，避免各自處理造成縫隙與重疊。
4. 首版可先使用未簡化幾何確保正確，再依實測資產大小決定是否加入離線、拓撲保真的簡化工具。若新增套件，限於所需地理運算並記錄選擇理由。
5. 低 zoom 顯示輪廓可容許約 1px 螢幕誤差作調校目標；選取輪廓與聚焦遮罩使用精細版本，避免可見區域與篩選結果互相矛盾。不能僅靠小數位數宣稱達成誤差預算。
6. 驗證閉合、有限座標、合理範圍、非自交、洞與拓撲有效性；現有 `validateGeometry` 只涵蓋部分檢查，不能當成完整拓撲驗證。

manifest 記錄來源日期、原始來源 hash、查詢／顯示 hash、處理版本與簡化誤差。查詢與顯示資產作為同一批產物交付。補上兩種來源皆能讀取本地 fixture 的匯入模式，測試不依賴官方服務；不得假定目前 `--file` 已涵蓋城市來源。

### 3.2 探索大區

新增人工維護的探索大區定義：`id`、英文／繁中名稱、`memberRegionIds`、排序、命名與分組理由。建議 ID 前綴 `hou-explore-`，kind 新增 `exploration`。

- 第一版只將 Houston 現有社區分組，周邊獨立城市維持 `city`，避免假設城市是某社區的子區。
- 每個社區恰屬於一個探索大區；所有引用存在且無重複歸屬。探索大區的幾何為成員完整幾何的離線 union，消除內部接縫。
- 依相鄰關係與可辨識地理位置形成分組，再以道路、河流及生活圈認知校對名稱。以方位名稱作初稿，具體成員與正式名稱在分組產物中確定，不憑空聲稱地方慣用名稱。
- 檢查連通性；若來源本身含離散部分，保留並記錄原因。不能用凸包、bbox 或自動吸附填滿空白。
- 當某道路穿過既有社區時，首版不沿道路再切社區。
- 顯示「探索分區／Explore areas」及簡短說明，明確區別官方社區與城市。

先產出分組表與全城預覽，檢查區名、大小差異、連通性與空白區，再接入正式畫面。沒有合格分組時，第一交付仍可獨立完成；探索大區保持未發布狀態。

## 4. 地圖視覺規格

以下數值是實作起點，須以真實底圖、桌面與手機截圖調校。

| 尺度               | 主層級             | 邊界與標籤                                                     |
| ------------------ | ------------------ | -------------------------------------------------------------- |
| zoom < 10.5        | 探索大區＋周邊城市 | 隱藏社區內部線；大區名優先，城市名次之；非常縮遠時繼續減少標籤 |
| 10.5 ≤ zoom < 13.5 | 社區＋周邊城市     | 探索大區線與標籤淡出，社區逐步出現；城市保留不同線型與文字樣式 |
| zoom ≥ 13.5        | 街道與地點         | 未選區的填色、邊線、區名淡出；聚焦區仍保留清楚輪廓             |

第一交付尚無探索大區時，低 zoom 僅顯示周邊城市與底圖地名，不能把細社區線重新塞回全城視角。

- 普通區界約 0.75–1px；hover 約 1.5px；選取約 2px。城市可用短虛線搭配類型文字，社區用實線，不能只靠色彩區分。
- 普通填色 0–3%，hover 約 5–7%；探索大區最多使用 3 個很淡的低飽和色，僅作辅助。禁止彩虹拼圖及與 marker 分類競爭的高飽和底色。
- 聚焦採一致的深青綠輪廓；區外遮罩先從 16% 試起，在 12–20% 間調校，保留道路與地名可讀性。
- 各層級標籤有碰撞避讓與優先序，不強制全部顯示。標籤點必須落在區內；底圖地名重複時優先減少 app 標籤。
- 淡入淡出使用約 150–200ms；reduced motion 停用装飾動畫。縮放切換只改圖層樣式，不重建 Mapbox instance。

## 5. 互動與狀態契約

維持 `hoveredRegionId`、`focusedRegionId`、URL `region` 三種語意。視覺層級由 zoom 決定；縮放不觸發查詢、不清除聚焦、不改 region。

| 操作或情境                 | 預期行為                                                             |
| -------------------------- | -------------------------------------------------------------------- |
| hover／點選區塊            | 只操作當前尺度可見、可互動的層級；透明隱藏層不可攔截點擊             |
| 點探索大區                 | 聚焦並顯示摘要，不自動移鏡頭或篩選                                   |
| 查看整區                   | 使用 bbox 加面板 padding 取景；bbox 不作查詢幾何                     |
| 只看此區                   | 所有 kind 共用同一 URL `region` 契約；探索大區以可信 union 幾何篩選  |
| 聚焦社區後縮遠             | 保留該社區的專用聚焦輪廓與摘要，其他社區仍隱藏                       |
| 聚焦大區後放大             | 大區外框保留，內部社區可探索；點社區只切換聚焦                       |
| 切尺度跨過轉場             | 命中層級在固定門檻切換，hover 先清除；視覺可平滑過渡，避免雙重 click |
| 城市與其他區域相接／重疊   | 按有效可見層與明確 kind 優先序判定；不依 GeoJSON 陣列順序隨機選取    |
| 點 marker／群聚            | 優先於區塊；不能連帶選到下方分區                                     |
| 無邊界、載入失敗、無 WebGL | 保留 marker／搜尋／列表與已生效的伺服器篩選及清除入口                |

選擇器分「探索分區」「社區」「周邊城市」三組，按名稱排序；所有尺度下均可由鍵盤選取任意區域。手機使用相同點選語意與現有浮動面板，不依賴 hover。摘要持續分別顯示聚焦區及結果範圍；點 A 區不能讓 B 區篩選悄悄消失。

探索大區啟用前，同步擴充 server registry、client summary、選擇器與驗證；不可只加前端 kind。保留 `region` 與矩形 `area` 的既有交集規則、權限與截斷前 polygon 篩選，不新增 DB schema。無座標／線上項目、外部即時搜尋沿用既有明示範圍規則。

| 0：基準       | 檢查工作目錄、相關指南與已安裝 Next.js 文件；記錄目前全城／社區／街道畫面及資產大小                                | 有可比較的基準、未提交工作界線與已知失敗清單                           |

## 7. 驗證計畫

### 行為與資料

- 擴充 `tests/unit/map-regions.test.ts`：洞、離散部分、凹形、边界包含、既有 ID、查詢／顯示版號一致；加入會被舊 `tidyCity` 錯誤納入或排除的點。
- 分組測試：未知成員、重複歸屬、缺漏、union 與成員查詢結果一致；保持来源本有的空白與洞。
- 新增尺度策略單元測試：門檻兩側、可見／可互動層級與 focus 例外；不為單純色碼寫鏡像測試。
- 擴充 `tests/integration/map.test.ts`：真實查詢幾何、探索大區 union、截斷前篩選、私有／隱藏資料、與 area 交集；DB 前確認為可丟棄測試資料庫且不輸出憑證。
- 擴充 `tests/e2e/map.spec.ts` 或新增專用測試：三尺度、點隱藏區、跨尺度聚焦、只看此區、清除、Back／Forward、marker 優先、鍵盤／手機與邊界載入失敗。
- 無法使用真實 Mapbox 時，可用固定 fixture 驗證狀態契約；須另外標記真實渲染與碰撞避讓尚未驗收。

### 視覺與效能

截圖矩陣：1440×900、1024×768、390×844、手機橫向、200% 縮放；英文／繁中。至少包含全城、尺度交界兩側、街道、長區名、密集 marker、城市 enclave、洞、多邊形離散部分與空白區。

驗收重點：能辨別城市／社區／探索大區；標籤不堆疊；選區與結果範圍清楚；浮動控制不遮擋關鍵操作；鍵盤焦點可見，控制點擊區至少 44px，文字對比目標 4.5:1。淡色輔助邊界不能是唯一操作入口。

記錄同裝置同資料下的資產 gzip 大小、解析時間、hover 延遲及切區長任務。沿用顯示資產 gzip ≤500KB、hover <50ms、避免切區 >100ms 主執行緒長任務作初始預算；這些是待量測目標。超標先評估按尺度載入與拓撲保真簡化，不犧牲查詢幾何。完整查詢資產不可透過 shared barrel 帶入所有 client bundle。

### 指令

使用 Node.js 22、pnpm 10.15.0，從根目錄執行。以下為實作後的檢查，不代表本次已執行：

```sh
pnpm lint
pnpm typecheck
pnpm exec vitest run tests/unit/map-regions.test.ts
pnpm test:integration
pnpm exec playwright test tests/e2e/map.spec.ts
```

## 8. 風險、回退與完成定義

- 精確城市邊界可能仍不規則：用尺度與線條降噪，不能為美觀修改真實歸屬。
- 探索分組未成熟：停留在已驗收的第一交付，並明確記錄第二交付未完成。
- union／簡化失敗：保留上一版完整有效產物，生成命令失敗退出，不寫入半套 registry／顯示資產。
- 新資產載入失敗：分區呈現降級，保留搜尋與清除篩選；若需回退版本，查詢與顯示必須一起回退。不得為視覺回退重新導入已知錯誤的城市查詢幾何。
- 完成報告包含各階段狀態、來源版本、真實執行的檢查與截圖、效能數據、已知限制及本地 commit。只提交本任務變更，不混入既有工作；push、部署及 live 環境操作另依使用者授權。
